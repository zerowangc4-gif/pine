# Pine 方向（为什么做、给谁做、做什么、不做什么）

> 这是方向性文档，不是技术文档。技术细节看 `AGENTS.md` 和 `apps/desktop/README.md`。

## 一句话方向

Pine 不是「给开发者再做一套 CLI 图形壳」，而是**给想做 AI 产品的人，一个可视、可扩展、可嵌入的桌面底座**。

## 给谁用（反复问「谁会用」）

1. **核心用户**：想在自己的项目文件夹里，让 AI 读代码/改代码/跑命令的**非 CLI 用户**（不记命令、不装终端、点开就用）。
2. **次级用户（也是做产品的人）**：拿 Pine 当底座，用 **skills + extensions** 往里面塞自己的领域能力，封装成垂直产品。

## 差异化（别人为什么不用 CLI 而用 Pine）

CLI（`pi`）已经赢了「开发者效率」，Pine 只能赢在这四点上，且必须做到位：

1. **可视化**：文件树点击、编辑器内看 diff、流式输出、每轮花费一眼可见。
2. **多模态**：拖图/贴图/右键粘图，模型直接看图。
3. **零门槛**：登录 → 打开文件夹 → 说话，不用学命令。
4. **可扩展**：skills 可视化新建/管理；extensions 加载自定义工具；这些都是「做其他产品」的命根子。

**不做**：和 CLI 比命令能力、比脚本效率、比终端集成——这些永远打不过，也不该打。

## 做什么（优先级，从高到低）

1. **把现有能力做稳**：图片、diff、会话、花费、技能管理，先把这些用顺。
2. **可视化差异**：编辑器 diff（已做）→ 文件树与对话联动 → agent 改动的可视化审阅。
3. **扩展能力**：skills 管理器升级（可编辑/导入/分享）、extensions 加载与工具展示。
4. **低门槛**：一键新建 skill、模型里标注「视觉」、清晰的错误提示。

## 不做什么（明确排除）

- MCP、Pi packages、OAuth 订阅登录（重活，SDK 不支持或投入产出比低）。
- 云同步、多工作区、插件市场（花哨，核心用户用不上）。
- 和 CLI 重复的「更强终端/更强命令」。

## 判断标准（每做一个功能前问）

- 谁会用？他为什么不用 CLI 做这件事？
- 这个功能是「可视化/多模态/零门槛/可扩展」里的哪一条？
- 如果不属于任何一条，先不做。
