Pine 开发指南

Pine 是一个 Electron 桌面端编码助手：连接模型 → 打开文件夹 → 与助手对话， 助手通过 read / bash / edit / write 工具在项目目录内工作。 本文档是唯一的开发入口，读完即可上手贡献代码。

Electron 37 React 19 TypeScript 5.9 Redux Toolkit + redux-saga styled-components i18next pi-coding-agent 0.85.1 pnpm 11

1项目概览

Pine 把 @earendil-works/pi-coding-agent（Pi 编码助手 SDK）嵌入自定义 GUI。 它不是 CLI 的简单套壳，核心卖点是：数据不出机、无账号、API key 只在内存、实时成本透明、Agent 每步可见。

2快速开始

  • Node.js 20+（推荐 22）
  • pnpm 11（仓库 packageManager 已锁定 pnpm@11.22.0）
E:\agents\pine

pnpm install

# 本地运行桌面端
pnpm dev

# 类型检查（无输出即通过）
pnpm typecheck

# Lint（eslint + prettier）
pnpm lint

# 生产构建（main / preload / renderer 三段，全部成功即通过）
pnpm build

等价的细粒度命令：

E:\agents\pine

cd apps/desktop && npx electron-vite build
⚠ 改完代码必须过质量门

至少跑 pnpm typecheck + pnpm lint；改动 main / preload（涉及 SDK 外部化、新依赖、IPC）后再跑 pnpm build 确认 bundling。

Feature 固定形状

每个 feature 必须照抄这套结构：

features/<name> 
types/state.ts          该 feature 的 Redux state 类型
store/slice.ts          createSlice（reducers + actions）
store/saga.ts           window.pi 副作用
store/index.ts          再导出 slice + saga
components/ 或 pages/   纯 UI 组件（多个导出时加 index.ts 桶导出）
index.ts                feature 对外导出

新增 feature 时，在 store/index.ts 挂 reducer、在 store/rootSaga.ts 挂 saga。

桶导出规则：一个文件夹有多个对外导出（尤其 services）时必须建 index.ts 桶导出，外部只 import 该文件夹，不 import 内部文件。

4SDK 边界与零默认配置

4.1 能力收敛到一处

主进程用到的所有 SDK 能力必须从 src/main/core/pi.ts 导入，禁止在业务代码里直接 import "@earendil-works/pi-coding-agent"。新增能力时先在该文件补一行导出。

4.2 零默认配置（本项目硬性要求）

Pi 默认会读 ~/.pi/agent/ 下的 settings / auth / models / SYSTEM.md / AGENTS.md / extensions / skills。桌面端必须零默认配置：

src/main/services/pine-service.ts（标准写法，照抄） 
import { ModelRuntime } from "@earendil-works/pi-coding-agent";
import { InMemoryCredentialStore } from "@earendil-works/pi-ai";

// 1) 模型运行时：内存凭证 + 不读 models.json
const runtime = await ModelRuntime.create({
  credentials: new InMemoryCredentialStore(),
  modelsPath: null,
});

// 2) 运行时注入 API key，不落盘
await runtime.setRuntimeApiKey(provider, apiKey);

// 3) 会话：内存设置 + 自定义 ResourceLoader（零磁盘发现）
const { session } = await createAgentSession({
  cwd: root,                 // 打开的工作目录，工具作用域
  agentDir: root,            // 传了自定义 loader 后不再参与发现
  model,                     // runtime.getModel(provider, modelId)
  thinkingLevel: "high",
  modelRuntime: runtime,
  resourceLoader,            // createProjectResourceLoader() 产物
  sessionManager: SessionManager.create(root, sessionsDir),
  settingsManager: SettingsManager.inMemory({
    compaction: { enabled: false },
    retry: { enabled: true, maxRetries: 2 },
  }),
  tools: BUILTIN_TOOLS,      // 内置工具全部保持可用；默认关闭/被禁用的工具由 tool-permission-gate 拦截并逐次弹窗审批
});

4.3 模型与鉴权

ModelRuntime 常用 API 
runtime.getProviders()                    // 所有内置 provider
runtime.getModels(providerId)             // 该 provider 的静态模型目录（无需网络）
runtime.getModel(providerId, modelId)     // 单个模型；不存在返回 undefined
runtime.setRuntimeApiKey(provider, key)   // 注入 key（仅内存）
runtime.hasConfiguredAuth(provider)       // 是否已配置凭证
runtime.completeSimple(model, context, { signal })   // 单次请求，返回 AssistantMessage

校验 key 是否有效用返回的 AssistantMessage.stopReason（"stop" | "error" | "aborted"）判断，而不是只靠是否抛异常。

5会话与事件流

5.1 事件归约

主进程把 SDK 的 AgentSessionEvent 归约成 ChatEvent（shared/types.ts）通过 IPC 推给渲染层，渲染层在 chat slice 里归约成消息列表。

SDK 事件归约为 ChatEvent渲染层动作
agent_startagent_startstreaming = true
message_start（assistant）assistant_start追加 assistant 气泡
message_update（text_delta）text_delta追加正文
message_update（thinking_delta）thinking_delta追加思考
message_end（assistant）assistant_end + message_usage结束气泡 + 记本条花费
tool_execution_starttool_start追加工具 chip（running）
tool_execution_endtool_end工具 chip 置 done/error
agent_settledsettled + session_stats结束 + 刷新会话列表与统计
message_end（任意 role）session_stats（微任务延迟）底部统计实时刷新
ℹ 统计的实时性

SDK 在 listener 执行之后才 appendMessage，所以 forwardEvent 里用 queueMicrotask 延迟一拍再读 getSessionStats()，保证读到刚写入的 message。

5.2 新增事件要改三处

  1. services/agent-event-adapter.ts 的 toChatEvents()
  2. shared/types.ts 的 ChatEvent 联合类型
  3. chat slice 的对应 reducer（store/slice.ts）

5.3 会话持久化

  • 会话自动保存到 app.getPath("userData")/sessions（Electron 标准目录，避免安装目录不可写）。
  • 续接用 SessionManager.open(path, dir, cwd)；列表按当前工作目录过滤。
  • IPC 边界防御：loadSession / deleteSession 的路径先经 resolveSessionPath()（即 path-utils.ts 的 resolveExistingWithinDir()）校验必须落在 sessions 目录内，防 .. 越界与符号链接逃逸。
  • 工具详情可审计：toolCall.arguments 已随消息持久化，重载时由 services/tool-call-description.ts 的 describeToolCall() 重新生成 summary/diff（bash 命令、edit/write diff 与实时流一致）。
  • 重命名 = sessionManager.appendSessionInfo(name)；自动压缩开关 = session.setAutoCompactionEnabled(bool)，并持久化到 sessions/session-settings.json（按会话路径索引，重载会话时读回，不再每次回默认关）。

6Redux / Saga 与 Feature 分层

6.1 命名约定

  • 触发异步的 action：*Request（空 reducer，payload 带输入）。
  • 记录结果的 action：*Success / *Failure。
  • reducer 必须纯；id 用 utils/id.ts 的 createId()（crypto.randomUUID）。
  • saga 不 import useTranslation：存 i18n key 或原始错误串，UI 渲染时翻译。
store/slice.ts 示例 
switchModelRequest(_s, _a: PayloadAction<{ provider: string; model: string }>) {},
switchModelSuccess(state, action) {
  state.selectedProvider = action.payload.provider;
  state.selectedModel = action.payload.model;
},
store/saga.ts 示例 
function* switchModelSaga(action) {
  const result = yield call(() => window.pi.switchModel(action.payload.provider, action.payload.model));
  if (result.ok) {
    yield put(switchModelSuccess({ provider: action.payload.provider, model: action.payload.model }));
  } else {
    yield put(chatError(result.error ?? "error.operationFailed"));
  }
}

6.2 切片注册

当前 store 有五个切片：theme、layout、login、workspace、chat；三支 saga：loginSaga、workspaceSaga、chatSaga。

7关键流程

7.1 登录 / 连接

Login → loadProviders → window.pi.listProviders() → PineService.listProviders()
  → 选 provider / model + API key → connectRequest → PineService.connect()
     （本地校验凭证/模型，不发网络 ping 校验）→ connected → navigate("/chat")

聊天页顶部的模型下拉框可换同 provider 的模型；换 provider 用下拉框旁的 ＋ 按钮（ConnectProviderModal）就地补 key，不必回登录页。流式生成期间切换模型被禁用（UI 禁用 + PineService.switchModel() 返回 error.streaming 双重防线）。

7.2 文件夹与文件

FileExplorer / workspace saga → window.pi.executeFile({ intent, ... })
  → files:execute → FileService.execute() 按 intent 分发（全异步 IO，不阻塞主进程）
FileService 用 resolveWithinRoot 校验路径不越出工作目录。
fs.watch(root, { recursive: true }) + 300ms 防抖 → files:changed → refreshTreeRequest

7.3 聊天

ChatView send → sendMessage（先落用户气泡）→ window.pi.sendMessage()
  → PineService.sendChatMessage() 懒建 AgentSession → session.prompt()
  → AgentSessionEvent → ChatEvent → chat:event → ChatPage → chat slice
  • 图片：粘贴 / 拖拽 / 右键粘贴 / 文件选择，base64 走 ImageContent；仅 acceptsImages 模型开放。
  • 流式中：输入框变「追问 followUp / 打断 steer」，对应 session.followUp() / session.steer()。
  • 花费：message_end 推 message_usage（每条回复下方）+ 底部实时总统计。

7.4 Extensions / 上下文文件

会话创建时从项目目录加载（不走全局默认配置）：

  • extensions：<root>/.agents/extensions
  • skills：<root>/.agents/skills
  • context files：项目 AGENTS.md / SYSTEM.md
  • 工具权限 gate：由 services/tool-permission-gate.ts 作为内联 extension 注入。

实现见 services/resources.ts。

8编码规范

8.1 新增 IPC 能力（五步，缺一不可）

  1. 类型：shared/types.ts 的 Pi 接口加方法 + 出入参类型。
  2. Channel：shared/ipc.ts 加 channel 常量（禁止手写字符串）。
  3. 桥接：preload/index.ts 暴露 window.pi.*。
  4. Handler + 逻辑：main/ipc/<域>.ts 写 ipcMain.handle，真逻辑放 PineService / services/*；用到新 SDK 能力先在 core/pi.ts 补导出。
  5. 渲染层：saga 调用 + 双语 i18n（zh-CN / en-US 都加）。

8.2 错误处理

  • 主进程已知失败返回 i18n key（shared/errors.ts 的 AppError，如 error.noFolder）；未知错误返回原始技术信息（toErrorMessage）。
  • 渲染层统一走 utils/error.ts 的 errorText()：是 key 就翻译，否则原文透传。
  • 新增错误码：errors.ts 加常量 + 两个语言包的 error.* 都加。

8.3 国际化

  • 所有用户可见文案走 t("feature.key")，禁止硬编码中/英文。
  • 每个 key 同时加到 i18n/locales/zh-CN.json 与 en-US.json。

8.4 主题与样式

  • 禁止硬编码颜色与间距：颜色用 theme.colors.*，间距用 theme.spaces["…"]（1=4px、4=16px）。
  • 只有 dark（默认）/ light 两套，由 theme/theme.ts 提供；新 token 先改 Theme 接口，再补两个主题的值。
  • 图标只放 components/icons.tsx；不引外部图标库。

8.5 共享 UI 原语

小控件统一从 components/ui.tsx 导入，不要在各处重复定义：

组件用途props
ModalButton弹窗 footer 按钮$primary?、$danger?
SwitchButton + SwitchKnob开关（权限 / 自动压缩）$on
TextInput带边框输入框（会话名 / key）原生 input props

8.6 整洁代码

  • 单一职责、命名清晰、无死代码 / 死导入 / 重复定义。
  • 通用工具放 renderer/utils/ 或 shared/utils.ts（跨进程时），不复制粘贴。
  • 新增依赖用 pnpm --filter @pine/desktop add <pkg>。

11产品方向与设计决策

一句话方向

Pine 不是「给开发者再做一套 CLI 图形壳」，而是给非 CLI 用户一个可视、可扩展、可嵌入的桌面底座。

给谁用

  • 核心用户：在自己的项目文件夹里让 AI 读代码 / 改代码 / 跑命令的非 CLI 用户。
  • 次级用户：拿 Pine 当底座，用 extensions 塞进自己的领域能力。

差异化（只赢这四点）

  1. 可视化：文件树、编辑器 diff、流式输出、每轮花费。
  2. 多模态：拖图 / 贴图 / 右键粘图。
  3. 零门槛：登录 → 打开文件夹 → 说话。
  4. 可扩展：extensions 加载自定义工具、工具权限逐次审批。

关键设计决策备忘

  • 文件树：无头部标题栏，所有操作走右键；fs.watch 自动刷新 + 窗口聚焦兜底，无手动刷新按钮。
  • 编辑器：行号与文本同步、Tab=2 空格、Ctrl/Cmd+S 保存；文件被外部修改后出现「查看改动」diff（diff 包）。
  • 模型切换：在聊天输入框下方（Cursor 风格），同 provider 分组；快速/深度二档对应 thinkingLevel low/high。
  • 会话：自动持久化、按工作目录过滤、可续 / 删 / 重命名 / 自动压缩。
  • 工具权限：八种内置工具（read / bash / powershell / edit / write / grep / find / ls）内存开关；开启的直接运行，关闭的每次使用前弹窗逐次审批。只读工具（read / grep / find / ls）永不弹窗；bash/powershell 默认关闭（首次尝试必弹窗）；edit/write 弹窗展示 diff 预览；bash/powershell 弹窗展示命令原文（默认折叠 + 复制 + 展开）。
  • 聊天工具详情：聊天窗口是主审阅面——bash/powershell 显示命令原文，edit/write 显示行 diff（复用 FileDiff），read/grep/find/ls 显示目标路径/搜索词。
  • 主题 / 布局 / 语言：仅 Redux 内存，不写 localStorage。

不做什么（明确排除）

MCP（SDK v0.85.1 无原生支持）、Pi packages、OAuth 订阅登录、云同步、多工作区、插件市场。
